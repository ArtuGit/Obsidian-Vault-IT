# CLAUDE.md

This file provides guidance to agents when working with code in this repository.

## What this repo is

Artu's personal IT knowledge base: an Obsidian vault (`content/`) published as a static site via Quartz 4 (everything at repo root). The vault content and the site generator live in the same repo — `content/` is the Obsidian vault root (has its own `.obsidian/` config), and the rest of the repo (`quartz/`, `quartz.config.ts`, `quartz.layout.ts`) is the mostly-vendored Quartz static site generator that builds `content/` into the `public/` directory.

## Commands

- `npm run dev` — build and serve the site locally with live reload (build --serve)
- `npm run build` — build the static site into `public/`
- `npm run check` — typecheck (`tsc --noEmit`) + Prettier check
- `npm run format` — apply Prettier formatting
- `npm test` — run tests via `tsx --test`

There is no separate lint script or single-test invocation beyond what `tsx --test` supports (pass a file path to run one test file, e.g. `npx tsx --test path/to/file.test.ts`).

## Deployment

`.github/workflows/deploy.yml` builds on every push to `main` (`npm ci` + `npm run build`) and deploys `public/` to GitHub Pages. There's no separate staging step — pushing to `main` publishes the site.

## Architecture

- **`content/`** — the actual Obsidian vault. Notes use Obsidian wikilinks (`[[Note Name]]`) for cross-references, not standard Markdown links. Folders are topical (Architecture, Cloud, Security, Storages, Frameworks/Libs, etc.); most notes have no YAML frontmatter, so dates/metadata are inferred from git/filesystem (see `CreatedModifiedDate` plugin config below).
  - `content/.obsidian/` — Obsidian app config, including installed community plugins: `templater-obsidian`, `quickadd`, `auto-note-mover`, `code-styler`, `table-editor-obsidian`, `graph-analysis`.
  - Quartz's `ignorePatterns` (in `quartz.config.ts`) excludes `private`, `templates`, `.obsidian`, and `README.md` from the build — content placed under `content/private/` or `content/templates/` will not be published.
- **`quartz.config.ts`** — the single source of truth for site behavior: page title/branding, theme colors/fonts, and the transformer/filter/emitter plugin pipeline. Quartz processes content in three plugin stages, always in this order:
  1. **transformers** — parse and mutate markdown/AST (frontmatter, dates, syntax highlighting, Obsidian-flavored/GFM markdown, TOC, link crawling, descriptions, LaTeX via KaTeX)
  2. **filters** — drop pages from the build (currently just `RemoveDrafts`)
  3. **emitters** — produce output files (content pages, folder/tag index pages, sitemap/RSS, static assets, favicon, 404 page)
- **`quartz.layout.ts`** — defines which UI components render on which page types (`defaultContentPageLayout` for single notes, `defaultListPageLayout` for folder/tag listings) and shared components (header/footer) across all pages. Editing page structure/UI means editing this file, not `quartz.config.ts`.
- **`quartz/`** — the Quartz generator itself (CLI, components, plugins, processors, static assets, i18n). Treat this as largely vendored framework code; most day-to-day changes to this repo are either new/edited notes in `content/` or configuration changes in `quartz.config.ts` / `quartz.layout.ts`, not edits inside `quartz/`.
- **`public/`** — build output, git-ignored, regenerated by `npm run build`.

## Notes on editing content

- New notes should follow the existing convention of wikilinks (`[[...]]`) for internal references — Quartz's `ObsidianFlavoredMarkdown` transformer resolves these along with Obsidian-style embeds and callouts.
- `defaultDateType: "modified"` in `quartz.config.ts` means displayed dates come from git/filesystem modification time by default (frontmatter can override per-note).
